# Эксплуатация

## Открыть панель

На сервере найдите команду туннеля в `/root/autopilot.txt` или в выводе установщика. Выполните её на своём компьютере, оставив терминал открытым. Пример команды (порт и адрес у каждого сервера свои):

```bash
ssh -L ПОРТ:127.0.0.1:ПОРТ root@АДРЕС_СЕРВЕРА
```

Затем откройте в браузере локальный URL панели из `/root/autopilot.txt`, например `http://127.0.0.1:ПОРТ/СЛУЧАЙНЫЙ_ПУТЬ/`. Войдите с логином и паролем из этого же файла. Панель слушает только loopback; при закрытии SSH-сессии туннель перестанет работать.

## Пользователи и подключение

Создайте пользователя, при необходимости задав ограничения:

```bash
autopilot user add ИМЯ --gb 100 --days 30 --devices 2
```

Нулевые или опущенные `--gb`, `--days` и `--devices` означают отсутствие соответствующего лимита. Посмотреть список, ссылки и QR-код, временно отключить, включить или удалить пользователя можно так:

```bash
autopilot user list
autopilot user link ИМЯ
autopilot user off ИМЯ
autopilot user on ИМЯ
autopilot user del ИМЯ
```

Основная ссылка подписки подходит для разных приложений: панель выбирает формат по приложению-клиенту. Команда `user link` также выводит отдельные подключения и ссылку Clash для Nikki/OpenClash. Добавьте ссылку в приложение либо отсканируйте QR-код. Файл `/root/autopilot.txt` содержит данные первого пользователя; выдавайте его содержимое только самому пользователю.

Страница `index.html` объясняет подключение и выбор приложения. Её можно открыть как локальный файл в браузере; введённая ссылка обрабатывается в браузере и не отправляется этой страницей на сервер.

## Сертификат

Установщик запрашивает сертификат Let's Encrypt на публичный IPv4. Для продления systemd-таймер запускает проверку раз в 12 часов; сертификат короткого срока действия — около 6 суток. Для выпуска и продления необходим доступный извне 80/TCP. Если Let's Encrypt недоступен, устанавливается самоподписанный сертификат. Для Hysteria2 и TUIC в этом случае клиенту может потребоваться разрешить такое соединение.

Проверить сертификат, запросить новый или перечитать его службами:

```bash
autopilot cert status
autopilot cert renew
autopilot cert reload
```

Состояние таймера и журнал продления:

```bash
systemctl status autopilot-cert.timer
journalctl -u autopilot-cert.service
```

Если первоначально был выдан самоподписанный сертификат, сначала откройте 80/TCP в сетевом экране хостера и UFW (если он используется), затем выполните `autopilot cert renew`.

## Уведомления

Telegram-уведомления необязательны. Настройка запросит токен бота и числовой ID чата; при сохранении отправляется тестовое сообщение. Проверка выполняется каждые 10 минут.

```bash
autopilot notify setup
autopilot notify test
autopilot notify status
autopilot notify off
```

## Резервное копирование и перенос

Копия включает базу панели, состояние установки и сертификаты. Она содержит секреты. Создать обычную копию или зашифровать её паролем:

```bash
autopilot backup
autopilot backup --encrypt
```

Автокопии шифруются ключом, который нужно хранить отдельно от сервера и копий. По умолчанию хранятся семь последних архивов; число можно задать флагом `--keep`.

```bash
autopilot backup auto on --keep 7
autopilot backup auto key
autopilot backup auto status
autopilot backup auto off
```

Для переноса скачайте архив, например командой, которую покажет Autopilot:

```bash
scp root@АДРЕС_СЕРВЕРА:/var/backups/autopilot/ИМЯ_КОПИИ.tar.gz .
```

Скопируйте архив на чистый поддерживаемый VPS и восстановите его. Для `.enc` Autopilot запросит пароль копии:

```bash
scp ИМЯ_КОПИИ.tar.gz root@НОВЫЙ_СЕРВЕР:/root/
ssh root@НОВЫЙ_СЕРВЕР
autopilot restore /root/ИМЯ_КОПИИ.tar.gz
```

При переносе на другой IP Autopilot переписывает старый IP на новый в тех подключениях, где он используется, а сертификат получает заново. Учетные записи и подключения берутся из базы панели. Файлы уведомлений и ключ автокопий в архив не включаются: настройте уведомления заново и отдельно сохраните ключ, если переносите зашифрованные автоматические копии.

Чтобы расшифровать архив отдельно, используйте:

```bash
autopilot backup decrypt /путь/к/копии.tar.gz.enc
```

## Обновление Autopilot вручную

У Autopilot нет команды сетевого обновления. Получите проверенную версию исходного пакета отдельно и перенесите каталог `autopilot/` в тот же путь на сервере. Команда установщика находится в `/usr/local/bin/autopilot`, сам пакет — в `/usr/local/lib/autopilot/autopilot`.

Например, если каталог с новой версией уже находится в текущей папке сервера, замените пакет целиком, чтобы не оставить файлы старой версии:

```bash
mv /usr/local/lib/autopilot/autopilot /usr/local/lib/autopilot/autopilot.prev
cp -a autopilot /usr/local/lib/autopilot/autopilot
autopilot --version
```

Если новая версия не запускается, верните сохранённый пакет:

```bash
rm -rf /usr/local/lib/autopilot/autopilot
mv /usr/local/lib/autopilot/autopilot.prev /usr/local/lib/autopilot/autopilot
```

Не заменяйте `/usr/local/bin/autopilot` произвольным файлом: это точка запуска установленного пакета.

## Удаление

Перед удалением сохраните ключ автоматических копий, если он включён: команда удаления удаляет `/etc/autopilot/backup.key`, а архивы в `/var/backups/autopilot` остаются. Без ключа зашифрованные автокопии не расшифровать. Затем Autopilot предложит сохранить дополнительную резервную копию в `/root`. После подтверждения удаляются его службы, настройки, панель, правила UFW, добавленные установщиком, и созданные файлы. Пакеты ОС, SSH-конфигурация, которую меняла команда защиты, и каталоги резервных копий остаются.

```bash
autopilot backup auto key
```

```bash
autopilot uninstall
```

Предварительно посмотреть план удаления без изменений:

```bash
autopilot uninstall --dry-run
```

## Типичные проблемы

**Порт 443 занят.** Установщик проверяет занятость 443/TCP и 80/TCP. Узнайте процесс и остановите или перенастройте его, затем повторите установку:

```bash
ss -ltnp 'sport = :443'
```

**Let's Encrypt не выдал сертификат.** Проверьте входящий 80/TCP у хостера и в UFW. Автоматически устанавливается самоподписанный сертификат; после открытия порта запросите сертификат снова:

```bash
autopilot cert renew
```

**Потеряли пароль панели.** Данные входа сохранены в файле, который читается только root:

```bash
sudo cat /root/autopilot.txt
```

**Нет доступа к панели.** Убедитесь, что SSH-сессия с туннелем всё ещё работает, локальный порт в команде совпадает с адресом браузера, а URL содержит путь панели из файла. На сервере проверьте службы:

```bash
autopilot status
systemctl status x-ui autopilot-nginx
```
